# 여우굴 예약 이메일 설치 가이드

고객은 홈페이지에서 예약 내용을 한 번 작성합니다. Apps Script가 구글 시트에 접수를 저장하고 알림 이메일을 보냅니다. 홈페이지에는 저장이 확인된 신청만 ‘접수 완료’로 표시합니다. 구글폼은 만들지 않습니다.

| 역할 | 계정 |
| --- | --- |
| Apps Script와 시트를 만들 계정 | `replate.kr@gmail.com` |
| 설치 및 테스트 중 알림 수신자 | `replate.kr@gmail.com` |
| 운영 전환 후 알림 수신자 | `replate.kr@gmail.com`, `foxcavebrew@naver.com` 두 곳 |

최초 설정은 테스트 모드입니다. `useProductionRecipient`를 직접 실행하기 전까지 대표님 주소로는 알림을 보내지 않습니다. 발송 주체와 실행 권한은 계속 `replate.kr@gmail.com`에 남습니다. 수신 주소 변경은 소유권 이관이 아닙니다.

## 이미 설치했다면: 예약 최대 인원을 5명으로 변경

1. 기존 Apps Script 프로젝트의 **Code.gs 전체**를 최신 [apps-script/Code.gs](../apps-script/Code.gs)로 교체하고 저장합니다. 자동 일정의 `maxParty`가 `5`로 변경되었습니다.
2. **배포 → 배포 관리 → 기존 웹 앱 수정(연필) → 버전: 새 버전 → 배포**합니다. 기존 `/exec` URL을 유지합니다. 홈페이지 push만으로 Google에 배포된 코드는 바뀌지 않습니다.
3. **수업 일정** 탭에 직접 입력한 행이 있다면 원하는 일정의 **D열 ‘최대 인원’을 5**로 바꿉니다. 수동 행이 자동 일정에 우선하므로 2로 남겨두면 그 시간은 계속 최대 2명입니다. 더 적은 인원을 받으려는 일정은 해당 제한을 유지할 수 있습니다.
4. 홈페이지를 새로고침하고 일정·시간을 선택합니다. 시간 안내에 **최대 5명**, 참여 인원에 **1~5명**이 표시되는지 확인합니다.

이미 자동 일정이 활성화되어 있다면 `setup`, 일정 활성화 함수나 이메일 수신자 함수를 다시 실행할 필요가 없습니다. 기존 예약의 인원·시간·마감 상태와 수신자 설정은 유지됩니다. 한 수업은 계속 한 팀만 받으며, 1명 예약도 겹치는 시간을 마감합니다.

수업료는 기존대로 **1명 35,000원·2명 65,000원**, **3~5명은 ‘상담 후 안내’**입니다. 추가 인원의 금액은 임의로 계산하지 않습니다.

## 같은 배포에서 정식 도메인 테스트와 운영 전환하기

최신 `Code.gs`를 적용하고 기존 웹 앱을 새 버전으로 갱신한 후, 편집기 상단에서 아래 함수 중 하나를 선택해 **실행**합니다. 이후 모드를 바꿀 때마다 재배포하거나 홈페이지의 `/exec` URL을 변경할 필요는 없습니다. 함수는 공통 설정 `DELIVERY_MODE`를 스크립트 속성에 저장하고, 웹 앱은 새 신청을 처리할 때 이 설정을 읽습니다. [Google 스크립트 속성 안내](https://developers.google.com/apps-script/guides/properties)

| 실행할 함수 | 신청할 곳 | 기록 | 예약 알림 수신자 |
| --- | --- | --- | --- |
| `useProductionRecipientTest` | `https://여우굴.com` 또는 www 주소, 로컬도 허용 | 실제 구글 시트 | `replate.kr@gmail.com`만 |
| `useProductionRecipient` | `https://여우굴.com` 또는 www 주소 | 같은 구글 시트 | `replate.kr@gmail.com`, `foxcavebrew@naver.com` |

1. 먼저 **useProductionRecipientTest → 실행**으로 설정합니다. health의 `mode`는 `TEST`로 표시됩니다. 기존 `useTestRecipient`도 같은 설정을 적용하는 호환용 함수입니다.
2. 예약 연동 코드가 배포된 **정식 홈페이지**에서 테스트 신청을 한 번 합니다. 시트 ‘예약 신청’ 한 행, 리플레잇 메일 한 통, 신청한 시간 마감을 확인합니다. 메일 제목에는 `[TEST]`가 붙습니다.
3. 테스트 신청의 예약 상태를 **취소**로 변경해 시간을 다시 엽니다. 테스트도 실제 시트에 기록되므로 확인 뒤 정리해야 합니다.
4. 확인이 끝나면 **useProductionRecipient → 실행**합니다. 이후 새 신청부터 두 곳으로 보냅니다. 테스트로 돌아가려면 **useProductionRecipientTest**를 다시 실행합니다.

함수 실행 자체는 메일을 보내거나 예약을 추가하지 않습니다. 가장 최근에 실행한 설정이 같은 프로젝트의 전체 웹 앱에 계속 적용되며, 이미 접수된 신청은 저장 당시 수신자를 유지합니다.

## 이미 설치했다면: 예약 알림을 리플레잇과 대표님 두 곳으로 보내기

1. 기존 Apps Script 프로젝트의 **Code.gs 전체**를 최신 [apps-script/Code.gs](../apps-script/Code.gs)로 교체하고 저장합니다.
2. **배포 → 배포 관리 → 기존 웹 앱의 수정(연필) → 새 버전 → 배포**를 실행합니다. 기존 `/exec` URL을 유지하면 홈페이지의 연결 설정을 바꿀 필요가 없습니다.
3. 편집기 상단 함수 목록에서 **useProductionRecipient → 실행**을 누릅니다. 로그에 `replate.kr@gmail.com,foxcavebrew@naver.com` 두 주소가 나오는지 확인합니다. 이미 운영 모드였다면 새 버전 적용만으로 이후 신청에 두 주소가 사용됩니다.

이후 **새 운영 예약**의 알림은 두 주소를 받는 사람으로 지정해 함께 발송합니다. 시트 S열 **알림 수신자**에도 두 주소가 저장됩니다. 수신자 변경만 할 때는 `setup`이나 일정 활성화 함수를 다시 실행하지 않아도 됩니다.

테스트 모드와 `sendTestEmail`은 계속 `replate.kr@gmail.com`에만 발송합니다. 운영 모드의 실제 접수는 공개 여우굴 홈페이지에서 검증하며, 로컬 주소의 접수는 허용하지 않습니다. 이전 신청의 대기 메일은 당시 저장한 수신자를 유지하고 이미 발송한 메일은 다시 보내지 않습니다.

## 이미 설치했다면: 일·월·화 90분 일정 적용

**2026년 10월 19일부터 종료일 없이 일요일·월요일·화요일에만 자동으로 일정을 엽니다.** 시작 시간은 `19:00`, `19:30`, `20:00`, `20:30`이며, 각 수업은 **90분·최대 5명·한 팀**입니다. 마지막 수업은 22:00에 끝납니다.

### 지금 적용할 순서

1. `replate.kr@gmail.com`으로 기존 **여우굴 예약 알림** Apps Script 프로젝트를 엽니다. **Code.gs 전체**를 최신 [apps-script/Code.gs](../apps-script/Code.gs) 내용으로 교체하고 저장합니다. 새 프로젝트나 시트를 만들 필요는 없으며 `setup`도 다시 실행하지 않아도 됩니다.
2. 구글 시트의 **수업 일정** 탭을 확인합니다. **직접 입력한 행은 자동 일정보다 우선합니다.** 예전 60분 일정이나 테스트용 행이 남아 있으면 아래 정리 기준을 먼저 확인하세요. 자동 일정만 사용할 경우 이 탭에는 제목 행만 있어도 됩니다.
3. 편집기 위쪽 함수 선택 목록에서 **enableWeeklyEveningSchedule**을 선택하고 **실행**합니다. 로그에 `주간 일정 활성화`, `일·월·화`, 네 시작 시간과 `각 90분`이 나오는지 확인합니다. 기존 예약과 이메일 수신 모드는 유지되며 메일은 보내지 않습니다.
4. **배포 → 배포 관리 → 기존 웹 앱 선택 → 수정(연필) → 버전: 새 버전 → 배포**를 누릅니다. **기존 `/exec` URL을 유지**합니다. 저장이나 함수 실행만으로는 공개 웹 앱의 코드가 갱신되지 않습니다. [Google 배포 관리 안내](https://developers.google.com/apps-script/concepts/deployments)
5. 홈페이지 예약 페이지를 새로고침하고 **일정 새로 확인하기**를 누릅니다. 예약이 없는 운영일을 선택했을 때 `19:00~20:30`, `19:30~21:00`, `20:00~21:30`, `20:30~22:00`이 나와야 합니다. 다음 달에도 일·월·화가 열리는지 확인합니다.

현재 `useProductionRecipientTest`로 설정했다면 그대로 **TEST 모드·리플레잇 단독 수신**입니다. 수신 모드를 바꾸기 위한 함수를 다시 실행할 필요는 없습니다. 기존 `enableDailyEveningSchedule` 함수 이름도 호환용으로 남아 있으며, 새 코드에서는 같은 주간 일정을 활성화합니다. 이전 활성화 설정도 이어받습니다.

### 기존 시트 정리 기준

- **예전 60분 수동 일정:** 새 자동 일정을 따르게 하려면 해당 **수업 일정** 행을 삭제합니다. 특정 시간의 수동 설정을 유지하려면 소요시간을 `90`으로 수정합니다. 수동 행의 체크만 해제하면 해당 시작 시간이 닫힌 상태로 유지됩니다.
- **수·목·금·토의 수동 일정:** 직접 등록하고 접수 열기를 체크한 행은 추가 수업으로 계속 열립니다. 예외 수업을 받지 않으려면 해당 행을 삭제하거나 접수 열기를 해제합니다.
- **예전 테스트 일정:** `2026-10-20 / 19:30 / 90` 테스트 행은 새 자동 시간과 일치합니다. 이 시간을 정상 개방하려면 해당 수동 행을 삭제해 자동 일정을 따르게 하거나 접수 열기를 체크합니다. 체크 해제 상태로 남겨두면 그 시간만 닫힙니다.
- **예전 테스트 신청:** **예약 신청** 탭의 `리플레잇 연동 테스트` 같은 가상 신청은 K열 예약 상태를 `취소`로 바꿉니다. 19:30 테스트 신청이 살아 있으면 네 시작 시간이 모두 겹쳐 해당 날짜가 마감됩니다.
- **이미 접수된 실제 예약:** 새 코드를 적용해도 저장된 시작 시간과 **D열 소요시간**은 자동 변경하지 않습니다. 기존 60분 예약을 90분으로 바꾸기로 확정했다면 D열을 `90`으로 조정해야 늘어난 시간까지 다른 신청을 막습니다. 기존 고객과 약속한 일정은 확인한 뒤 수정하세요.

### 예약 후 시간대가 닫히는 기준

다른 예약이 없고 시작 시간이 아직 지나지 않은 경우입니다. 한 팀이 접수되면 실제 수업 시간이 겹치는 시작 시간만 닫습니다. 종료와 시작이 정확히 맞닿는 수업은 겹치지 않습니다.

| 예약된 수업 | 남는 예약 가능 시작 시간 |
| --- | --- |
| 19:00~20:30 | 20:30 |
| 19:30~21:00 | 없음 — 해당 날짜 마감 |
| 20:00~21:30 | 없음 — 해당 날짜 마감 |
| 20:30~22:00 | 19:00 |

19:00과 20:30 두 팀을 받으면 해당 날짜 전체가 마감됩니다. 확정 전인 `접수 대기`도 시간을 차지하며, `취소` 또는 `진행 불가`가 되면 아직 미래이고 다른 예약과 겹치지 않는 시간만 다시 열립니다. 동시에 신청한 경우 서버가 겹치는 두 번째 신청을 거절합니다.

홈페이지 달력은 **신청 가능한 시간이 하나라도 있으면 ‘신청 가능’, 없으면 모두 ‘마감’**입니다. 지난 날짜, 수업 시작 시간이 지난 날짜, 휴무일, 직접 닫은 날짜, 예약으로 찬 날짜도 ‘마감’으로 표시합니다. 여기서 ‘마감’은 현재 온라인 접수가 불가능하다는 뜻입니다. 페이지를 열어둔 동안 시간이 지나면 새 예약 선택을 막으며, 이미 접수했지만 응답만 잃은 신청은 같은 접수번호로 재확인할 수 있습니다.

### 특정 날짜를 쉬거나 추가로 열기

자동 일정은 월별로 계산하므로 시트에 날짜를 끝없이 추가할 필요가 없습니다. **자동 일정은 ‘수업 일정’ 탭에 행으로 쌓이지 않으며**, 고객 신청만 ‘예약 신청’ 탭에 저장됩니다.

하루 전체를 쉬려면 **수업 일정**에 아래처럼 네 행을 등록하고 접수 열기를 모두 해제합니다. 하나만 닫으면 나머지 시작 시간은 열려 있습니다.

| 날짜 YYYY-MM-DD | 시작 시간 HH:mm | 소요시간 분 | 최대 인원 | 접수 열기 |
| --- | --- | --- | --- | --- |
| 2026-10-25 | 19:00 | 90 | 5 | 해제 |
| 2026-10-25 | 19:30 | 90 | 5 | 해제 |
| 2026-10-25 | 20:00 | 90 | 5 | 해제 |
| 2026-10-25 | 20:30 | 90 | 5 | 해제 |

- 같은 날짜·시작 시간의 수동 행을 삭제하면 해당 자동 일정이 다시 적용됩니다.
- 특정 시간의 인원이나 길이는 같은 날짜·시작 시간 행의 값을 바꿉니다. 이미 저장된 신청에는 소급 적용되지 않습니다.
- 휴무 요일에 추가 수업을 열려면 원하는 날짜·시작 시간·소요시간·인원을 등록하고 접수 열기를 체크합니다.
- 전체 자동 일정을 중지하려면 **disableWeeklyEveningSchedule**, 다시 열려면 **enableWeeklyEveningSchedule**을 실행합니다. 직접 입력한 일정은 유지됩니다. 새 코드를 한 번 배포한 뒤 활성화 상태만 바꿀 때는 재배포하지 않아도 됩니다.
- 메일 서식 확인용 **sendTestEmail**은 항상 리플레잇 주소로만 예시 메일을 보내며 예약 행을 만들지 않습니다. 메일의 항목명은 굵게 표시됩니다.

## 1 구글 프로젝트 만들기

1. [Google Apps Script](https://script.google.com/)에 **replate.kr@gmail.com**으로 로그인합니다. 오른쪽 위 계정을 확인하세요.
2. **새 프로젝트**를 누르고 이름을 **여우굴 예약 알림**으로 바꿉니다.
3. 기본으로 열린 **Code.gs** 내용을 모두 지웁니다.
4. 프로젝트 파일 [apps-script/Code.gs](../apps-script/Code.gs) 전체를 복사해 붙여넣고 저장합니다.

다른 HTML 파일이나 구글폼, 별도 API 키는 필요 없습니다. Gmail 비밀번호를 코드에 넣지 않습니다.

## 2 setup 실행하기

1. 편집기 위 함수 선택 목록에서 **setup**을 선택합니다.
2. **실행**을 누릅니다.
3. 권한 요청이 나오면 `replate.kr@gmail.com` 계정을 선택하고, 직접 만든 스크립트의 스프레드시트·메일 발송·트리거 실행 권한을 승인합니다.
4. 실행 로그의 **시트 링크**를 엽니다.

‘여우굴 클래스 예약’ 스프레드시트에 아래 두 탭이 만들어집니다.

| 탭 | 쓰임 |
| --- | --- |
| **수업 일정** | 홈페이지 달력에 표시할 실제 수업 일정을 입력 |
| **예약 신청** | 접수 내역, 예약 상태, 이메일 발송 상태 확인 |

`setup`은 메일 실패를 재시도하는 **10분 주기 트리거**도 만듭니다. 다시 실행해도 기존 신청과 일정을 삭제하지 않고 같은 트리거를 중복 설치하지 않습니다. 기본으로 생성된 빈 시트가 추가로 있어도 사용하지 않으면 됩니다.

구글의 미검증 앱 안내가 나타날 수 있습니다. 본인이 방금 만든 프로젝트인지 확인하고 해당 프로젝트의 승인 절차를 진행하세요. 조직 정책에 의해 차단되면 해당 계정에서는 공개 웹 앱 배포가 제한될 수 있습니다.

## 3 테스트할 수업 일정 넣기

**수업 일정** 탭의 2행에 테스트할 미래 날짜를 입력합니다. 아래 날짜는 예시이며, 설치하는 날보다 이후 날짜로 바꾸세요.

| 날짜 YYYY-MM-DD | 시작 시간 HH:mm | 소요시간 분 | 최대 인원 | 접수 열기 |
| --- | --- | --- | --- | --- |
| 2026-11-08 | 19:30 | 90 | 5 | 체크 |

- 날짜는 `2026-11-08`, 시간은 `19:30`처럼 입력합니다. A·B열은 텍스트 형식으로 준비됩니다.
- 직접 입력한 일정은 **접수 열기** 체크박스를 체크해야 신청할 수 있습니다. 일·월·화 자동 일정은 위의 `enableWeeklyEveningSchedule`로 별도 활성화합니다.
- 시간대는 한국 시간입니다.
- 같은 날짜와 시간을 중복으로 입력하지 않습니다.
- 테스트 일정은 실제 운영 전에 체크를 해제하거나, 실제 진행 가능한 일정으로 정리합니다.

한 일정은 한 팀만 받습니다. 신청이 저장되면 그 일정과 시간이 겹치는 일정은 마감됩니다. **예약 신청 → 예약 상태**를 `취소` 또는 `진행 불가`로 바꾸면, 아직 미래이고 일정이 열려 있으며 다른 신청과 겹치지 않을 때 다시 열립니다. `접수 대기`, `예약 확정` 상태에서는 계속 마감됩니다. 홈페이지에서 작성한 내용을 구글 시트에 저장하는 방식이며 구글폼 제출을 감시하는 기능은 아닙니다.

## 4 테스트 메일 보내기

1. Apps Script 편집기에서 함수 **sendTestEmail**을 선택합니다.
2. **실행**을 누릅니다.
3. `replate.kr@gmail.com`의 받은편지함에서 **[여우굴 TEST] 이메일 연결 확인** 메일을 확인합니다. 없으면 스팸함도 확인합니다.
4. 본문의 시트 링크가 열리는지 확인합니다.

이 함수는 테스트 주소로만 보내며 예약 행을 추가하지 않습니다. 이 단계는 메일 연결 확인이며, 홈페이지의 전체 접수 테스트는 6단계에서 진행합니다.

## 5 웹 앱 배포하고 홈페이지에 연결하기

1. Apps Script 오른쪽 위 **배포 → 새 배포**를 누릅니다.
2. 유형 선택에서 **웹 앱**을 선택합니다.
3. 아래와 같이 설정합니다.

| 설정 | 선택할 값 |
| --- | --- |
| 설명 | 여우굴 예약 접수 |
| 실행 사용자 | **나 — replate.kr@gmail.com** |
| 액세스 권한 | **모든 사용자** — 로그인하지 않은 방문자도 이용 가능 |

4. **배포**를 누르고 **웹 앱 URL**을 복사합니다.
5. URL이 `https://script.google.com/macros/s/…/exec` 형태인지 확인합니다. `/dev` 주소나 스크립트 편집기 주소는 사용하지 않습니다.
6. foxcave의 [site/booking-config.json](../site/booking-config.json)을 다음처럼 수정합니다.

```json
{
  "webAppUrl": "https://script.google.com/macros/s/여기에_발급된_배포_ID/exec"
}
```

이 파일에 넣는 것은 배포 URL 한 개뿐입니다. 이메일 주소와 비밀번호는 넣지 않습니다. 파일을 수정한 홈페이지가 서비스되어야 연결이 적용됩니다. 배포 URL이 비어 있으면 홈페이지는 접수 준비 안내를 표시하고 신청 버튼을 비활성화합니다.

웹 앱 URL 뒤에 `?action=health`를 붙여 **로그아웃 상태 또는 시크릿 창**에서 열어보세요. 아래처럼 표시되어야 합니다.

```json
{"service":"foxcave-booking","version":1,"ok":true,"mode":"TEST"}
```

로그인 화면이 나오면 액세스 권한을 다시 확인합니다. ‘모든 Google 계정 사용자’는 익명 접근과 다릅니다. 고객은 구글 계정으로 로그인하거나 권한을 승인할 필요가 없어야 합니다. [구글 웹 앱 배포 안내](https://developers.google.com/apps-script/guides/web)

## 6 홈페이지에서 실제 접수 테스트하기

테스트 모드를 유지한 채, 연결된 홈페이지의 `/booking/`을 엽니다. 로컬 테스트 주소는 `http://localhost:포트` 또는 `http://127.0.0.1:포트`를 사용할 수 있습니다. 파일을 더블클릭한 `file://` 방식은 사용하지 않습니다.

1. 등록한 날짜와 시간을 선택합니다.
2. 이름에 **테스트 신청**, 연락처에는 본인이 사용하는 테스트 연락처, 요청사항에는 **운영 전 연결 점검입니다**를 입력합니다.
3. 개인정보 수집·이용 동의 후 **예약 신청하기**를 누릅니다.
4. 홈페이지에 **신청이 접수되었어요**, 선택한 일정, 인원, 접수번호가 표시되는지 확인합니다.
5. 시트 **예약 신청** 탭에 **한 행만** 추가되는지 확인합니다.
6. `replate.kr@gmail.com`에서 **[TEST] [여우굴] 클래스 예약 신청** 메일을 확인합니다.
7. 메일에 이름, 연락처, 일정, 인원, 요청사항, 해당 시트 행 링크가 있는지 확인합니다.
8. 새 창에서 해당 일정을 다시 확인해 마감으로 표시되는지 확인합니다.
9. 테스트 행의 **예약 상태**를 `취소`로 바꾸고 **일정 새로 확인하기**를 눌러 다시 열리는지 확인합니다.
10. 휴대폰에서도 한 번 신청해 화면과 실제 메일 수신을 확인합니다.

**메일 상태가 ‘발송 완료’라는 것과 받은편지함에 도착했다는 것은 다릅니다.** 위 6번은 수신함에서 직접 확인해야 합니다. 테스트 완료 전에는 대표님 수신자로 전환하지 마세요.

## 7 리플레잇과 대표님 두 곳으로 운영 알림 전환하기

1. 실제 접수 테스트가 끝나면 Apps Script 함수 **useProductionRecipient**를 선택하고 **실행**합니다.
2. 로그에 `replate.kr@gmail.com,foxcavebrew@naver.com` 두 주소가 나오는지 확인합니다.
3. `?action=health` 응답의 `mode`가 **PRODUCTION**인지 확인합니다.
4. 실제 운영할 일정만 열고 홈페이지를 반영합니다.

이후 새 신청 알림은 `replate.kr@gmail.com`과 `foxcavebrew@naver.com`에 함께 보냅니다. **최신 코드가 배포된 이후의 모드 전환은 다시 배포할 필요가 없습니다.** 기존의 단일 수신자 버전에서 바꾸는 경우에는 먼저 새 코드 배포가 필요합니다. 이미 접수된 신청의 재시도 메일은 당시 저장한 수신자를 유지합니다. 테스트로 돌아가려면 **useProductionRecipientTest**를 실행합니다. 운영 모드에서는 로컬 주소의 신청을 받지 않습니다.

대표님은 이메일 본문에서 내용을 바로 읽을 수 있습니다. **시트 링크를 열고 예약 상태를 바꾸려면 별도 시트 접근 권한이 필요합니다.** 시트 오른쪽 위 **공유**에서 대표님이 로그인하는 Google 계정을 편집자로 초대하세요. Naver 수신 주소를 지정했다고 시트 접근 권한이 자동으로 생기지는 않습니다. 시트를 ‘링크가 있는 모든 사용자’에게 공개하지 않습니다.

`replate.kr@gmail.com`이 프로젝트 소유자이므로 해당 계정의 권한과 트리거는 계속 유지해야 합니다. 협업 종료 후 이 계정을 계속 운영할 수 없다면, 대표님 소유 Google 계정에 코드 복사 → `setup` → 새 웹 앱 배포 → 홈페이지 URL 변경이 필요합니다. 수신 주소 변경만으로 이 작업이 해결되지는 않습니다.

## 일상 운영

- **확정 연락 후:** 시트 K열 **예약 상태**를 `예약 확정`으로 변경합니다. 고객에게 자동 확정 문자나 이메일을 보내지는 않습니다.
- **취소 또는 진행 불가:** 해당 상태로 바꾸면 다음 일정 조회 때 다시 신청 가능 여부에 반영됩니다.
- **메일 실패:** L열 **메일 상태**를 확인합니다. `재시도 대기`는 10분 주기 작업이 최대 3회까지 발송을 시도합니다. 일일 메일 한도가 소진된 경우에는 한도가 돌아온 뒤 시도합니다.
- **재시도 종료:** 권한·한도를 해결한 뒤 해당 행의 N열 **메일 시도 횟수**를 `0`, L열 **메일 상태**를 `재시도 대기`로 바꾸고 `retryPendingNotifications`를 실행합니다.
- **확인 필요:** 발송 도중 실행이 중단되어 성공 여부가 불명확한 상태입니다. 받은편지함을 먼저 확인합니다. 이미 도착했다면 L열을 `발송 완료`로, 미도착이 확인되면 위 재시도 방법으로 처리합니다.
- **메일 수신 후 행 정렬:** 이메일 링크는 접수 당시 행 위치입니다. 시트를 정렬했다면 메일의 전체 접수번호로 검색하세요.
- **코드 수정:** Apps Script 코드 자체를 바꿨다면 **배포 → 배포 관리 → 수정 → 새 버전 → 배포**로 기존 URL을 갱신합니다. 편집기에서 저장만 하면 운영 웹 앱은 갱신되지 않습니다.

공개 예약 기능에는 하루 전체 80건, 같은 연락처 하루 3건 제한이 있습니다. 기본 개인 Google 계정의 Apps Script 메일 한도는 하루 수신자 합계 100명이며 다른 스크립트의 사용량도 영향을 줄 수 있습니다. **운영 예약 한 건은 수신자 2명분을 사용**하므로, 다른 발송이 없다면 이 한도로 예약 알림 50건을 보낼 수 있습니다. 잔여 수신자 한도가 2명분보다 적으면 접수는 저장하고 메일은 대기시켰다가 재시도합니다. 테스트 메일도 한도에 포함됩니다. [공식 한도](https://developers.google.com/apps-script/guides/services/quotas), [MailApp의 수신자·한도 설명](https://developers.google.com/apps-script/reference/mail/mail-app)

## 문제가 생겼을 때

| 증상 | 확인할 곳 |
| --- | --- |
| ‘온라인 예약을 준비하고 있어요’ | `booking-config.json`에 `/exec` URL을 넣었는지 확인 |
| 달력에 날짜가 열리지 않음 | 새 코드 배포·enableWeeklyEveningSchedule 실행 여부, 수업 일정의 날짜·시간·접수 열기 체크, 겹치는 기존 신청 확인 |
| ‘수업 일정을 정리하고 있어요’ | 일정표의 잘못된 행, 같은 날짜·시간 중복, 소요시간 30~240분, 인원 1~20명 확인 |
| 로그인 화면 또는 JSON 대신 HTML | 웹 앱 배포의 실행 사용자와 익명 접근 권한, `/exec` URL 확인 |
| ‘접수 결과를 확인하지 못했어요’ | 동일 내용을 유지해 재시도. 같은 접수번호는 중복 저장하지 않음. 시트와 Apps Script 실행 내역도 확인 |
| 시트에는 저장됐으나 메일이 없음 | 메일 상태, 권한, 일일 한도, 수신함·스팸함 확인 |
| 대표님이 시트 링크를 못 엶 | 대표님 Google 계정에 시트를 공유했는지 확인 |
| 미리보기 도메인에서만 접수 거절 | `Code.gs`의 `FC.ORIGINS`에 해당 HTTPS 출처를 추가하고 새 버전 배포. 기본은 여우굴.com 및 www 주소 |

프론트는 `text/plain` POST로 전송하고 JSON 성공 응답을 확인합니다. 구글의 응답 리다이렉트를 따라가도록 구현되어 있습니다. **`mode: 'no-cors'`로 바꾸지 마세요.** 읽을 수 없는 응답을 성공으로 처리하면 실제 저장 실패를 고객이 알 수 없습니다. [구글 Content Service 안내](https://developers.google.com/apps-script/guides/content)

## 개발 검증 범위

이 변경의 대상은 **클래스 예약 페이지**입니다. `/inquiry/`의 일반 문의, 기존 `/admin/`, 이전 `/booking/status/` API는 연결하지 않습니다. 새 클래스 예약은 같은 화면에서 접수를 확인하며, 일정 관리와 상태 변경은 구글 시트에서 합니다.

로컬 자동 검증은 Google 서비스를 대체한 메모리 환경에서 실제 `Code.gs`를 실행합니다. Google 로그인·권한·실제 Sheets·Gmail·Naver 수신함과의 연동을 대신 검증하지 않습니다. 실제 배포 후 4~7단계를 완료해야 운영 연결 검증이 끝납니다. 별도의 Google 계정 로그인 정보나 배포 URL이 제공되지 않았다면 실제 발송 검증은 미완료입니다.
